# Notes design-sync — SiteForge (site-json)

- Repo = **application** Vite (générateur de sites JSON), pas un package publié : pas de dist/ librairie ni de `.d.ts` shippés → entrée synthétisée via la barrel curée `.design-sync/ds-entry.ts` (`--entry`), alias `@/*` résolus par `tsconfig.app.json`.
- Périmètre : `src/components/ui/*` (shadcn, star exports) + `src/components/sections/*` (default → named). Exclus : `SectionRenderer`, `SectionEmptyState`, `HeroBackgroundImage`, `responsiveGridCols` (internes), et tout `src/modules/*` (search/blog/agenda/news… exigent le backend Cocolight).
- **Thèmes variables par config, c'est le principe du produit** (dixit l'utilisateur) : le DS embarque le thème PAR DÉFAUT (src/index.css, Quicksand + Playfair Display) comme base active ; les composants consomment les tokens `--primary`/`--accent`/`--chart-*`… — re-thémer = surcharger les variables (à documenter dans conventions.md), jamais de couleurs en dur.
- CSS : compilé par `npm run build:client` (Tailwind 4) puis concaténé avec les `@import` Google Fonts dans `.design-sync/.cache/ds-styles.css` (voir `buildCmd`). Le nom du fichier dist est hashé → toujours re-concaténer après build.
- Fonts : Google Fonts au runtime (l'app les charge via GoogleFontsLoader) → `@import url(googleapis)` dans la feuille + `runtimeFontPrefixes` pour les familles des thèmes de sites.
- Contextes requis par les sections : router (NavLink), SiteProvider (config minimale), LocalizationProvider (fr) → `.design-sync/ds-provider.tsx` via `extraEntries`, `provider.component: "DsProvider"`.
- **Images** : `OptimizedImage` proxifie tout par `/img?url=…` (inexistant hors de l'app) SAUF `data:`/`blob:`/`.svg` → les aperçus (et l'agent, via conventions.md) doivent utiliser des data-URIs SVG ou des URLs .svg.
- Le serveur dev de l'utilisateur tourne en continu (port 5173) sur ce node_modules : ne jamais relancer `npm ci` pendant une session.
- Piège shell : `cd` PERSISTE entre les appels Bash de Claude Code — un `cd .ds-sync && npm i` a fait tourner le build suivant au mauvais endroit. Toujours revenir à la racine.
- Exclusions barrel supplémentaires (fuites de graphe) : `TabsSection`/`GridLayoutSection` (importent SectionRenderer → tout src/modules + api-client → builtins node), `HeroSearch` (module search/autocomplete), `ExpandableActions` (ModalRegistry profil). Les primitives `Tabs`/`Table` de ui/ restent disponibles.
- `lucide-react` (0.556) n'a pas d'exports map et expose `dynamic.mjs` ; esbuild ne résout pas `.mjs` sans aide → alias `"lucide-react/dynamic"` dans `.design-sync/tsconfig.json` (le plugin paths du converter ne suit PAS `extends` : les paths doivent être inline dans le fichier pointé par cfg.tsconfig).
- Known render warns (triage validé) : `[TOKENS_MISSING] --radix-navigation-menu-viewport-{height,width}, --tw, --harvest` = variables posées AU RUNTIME (Radix/JS), attendues absentes des feuilles statiques — ne pas chasser.
- Learnings vague 1 (sections, fusionnés) :
  - Le CSS du bundle DOIT être buildé avec `SITE_CSS_PATH=$PWD/src/index.css` — le `.env` du repo porte un `VITE_SLUG` de travail (parent62…) qui sinon compile le thème du site courant (tokens de statut `--color-info/success/warning/error` absents des CSS de sites → BannerSection sans teinte).
  - Animations JS non gelées par le provider (le gel CSS ne suffit pas) : StatsSection `animated:false`, TestimonialsSection `autoplay:false`, ChartSection/recharts (react-smooth sur rAF) → patch rAF scopé dans le preview ChartSection (offset +5s/frame). Symptôme type : courbes figées à ~55 %.
  - Overlay `position:fixed` (CookieConsent) : wrapper `transform: translateZ(0)` dans le preview = containing block → capture dans la cellule, pas besoin de cardMode single.
  - Data-URI SVG dans `url()` CSS : `encodeURIComponent` laisse `()'` → formes plates + couleurs hex uniquement, pas de gradients `url(#id)`.
  - Largeur de capture ≈ breakpoint md : grilles `lg:` à 2 colonnes, splits empilés = état responsive réel, pas un défaut.
  - EventListSection filtre « À venir » par défaut → dates futures dans les previews.
  - CardsSection variant `event` : texte blanc sur image — pâle sur placeholders pastel, pensé pour de vraies photos (accepté).
- BUG PRODUIT trouvé par la vague (hors sync, à corriger dans l'app) : `CTASection` variant `outline` + `backgroundImage` → libellé invisible (`text-background` sur bouton outline déjà `bg-background`) ; combinaison présente dans `config.prod.json`.
- `HeroEntityBanner` : `cfg.overrides.skip` (useCocolight hors provider → non rendable statiquement) — carte plancher assumée.
- `cfg.overrides.<Name>.skip` = LISTE de stories à sauter (pas un booléen — `true` crashe emit.mjs). Un composant API-bound SANS preview autoré n'a besoin d'AUCUN override : sa carte plancher gère le crash (HeroEntityBanner).
- Overrides de présentation posés en fin de vague 1 : cardMode column (BlogList/BlogPost/Cards/Content/CtaCardGrid/EventList/FeaturesGlass), single+primaryStory Bandeau (CookieConsent).
- Learnings vague 2 (ui, fusionnés) :
  - `toast` ré-exporté dans ds-entry.ts (même instance sonner que le Toaster du bundle) — sans ça, un `toast()` d'une 2e copie sonner n'atteint jamais le Toaster (store module-scope).
  - Les previews ne peuvent utiliser QUE les classes Tailwind présentes dans le CSS compilé de l'app ; tailwind-merge peut évincer une classe de base au profit d'une classe inexistante → layout des previews en styles inline.
  - Overlays Radix : état ouvert statique OK (`open`/`defaultValue`) ; ContextMenu = dispatch MouseEvent("contextmenu") au mount ; 12 composants en cardMode single (posés en config).
  - Calendar (rdp v9) : toujours borner `startMonth`/`endMonth` sinon clamp hors mois demandé ; dates FIXES dans les previews.
  - Sidebar : `collapsible="none"` seul mode capturable ; recharts composable depuis node_modules (react shimé window.React) avec le patch rAF de ChartSection.
  - Remontées produit : pagination.tsx « Previous/Next » hardcodés anglais ; MultiCombobox sans prop `open` (carte menu-ouvert impossible sans ça).

## Learnings sync 2026-07-29 (re-sync après 60 commits src/)

- **Le diff du driver ne voit PAS les renommages de props amont.** Les grades sont keyés sur le `.tsx` d'aperçu + la config, pas sur la source du composant : 7 composants mappés avaient changé de source et sont tous ressortis `unchanged`. C'est `CagnotteSuccessScreen` (prop `milestoneReached` → `objectiveReached`) qui l'a trahi, et UNIQUEMENT via le warn `[RENDER_THIN] variants render identically` — la prop inconnue valait `undefined`, donc les 2 variantes tombaient dans la même branche. **Réflexe de re-sync : `git diff <dernier commit design-sync>..HEAD` sur les chemins de `componentSrcMap`, puis relire les interfaces `*Props` des composants touchés.** Un warn thin/variants-identical sur un composant dont la source a bougé = suspicion de dérive d'API, jamais un faux positif à enregistrer.
- Corollaire : les renommages de FICHIERS, eux, sont détectés (chemin absent de `componentSrcMap` → composant manquant). Vague cagnotte : `CagnotteMilestoneList` → `CagnotteItemList` (+ props `milestones/activeMilestoneIds/onMilestoneClick` → `items/activeItemIds/onItemClick`) et `CagnotteProjectProgressCard` → `CagnotteResourceProgressCard`. Les deux exigent désormais `cagnotteConfig: CagnotteTypeConfig` + `context: string` : le contexte i18n vaut `cagnotteConfig.selectorType + context`, donc `selectorType: "project"` retombe sur `resourceCagnotte` (« Cagnotte du projet ») et `"proposition"` sur `resourceCagnotte_proposition`. Mock = littéral inline calqué sur `CAGNOTTE_TYPE_CONFIGS` (src/modules/cagnotte/types.ts) — à resynchroniser si ce type gagne des champs.
- Renommer un composant = 4 endroits à toucher, sinon carte plancher ou export manquant : `componentSrcMap`, `ds-entry.ts`, `.design-sync/previews/<Name>.tsx` (renommer le fichier), et laisser le diff produire les `upload.deletePaths` des anciens chemins.
- `--spot-check-components` fait exactement ce qu'il faut pour auditer une vague : grades conservés, sheets refraîchies, et il n'efface QUE les grades dont le contrat a bougé (ici `CagnotteSuccessScreen` seul, ce qui a confirmé que le fix était bien pris en compte).
- Constat produit (même famille que CTASection outline / CagnotteAmountPicker) : `CagnotteSuccessScreen` pose un Badge `bg-linear-to-r from-primary to-accent` + `text-primary-foreground` ; en thème défaut neutre l'extrémité accent est très claire → fin du libellé en blanc sur clair. Lisible dès que le thème de site a un accent soutenu.
- Occasion d'authoring laissée ouverte : `footer.partners.note` (mention de financement, ajouté par e4ecaa5c) n'est couvert par aucune story de `FooterContactPartners` — le champ est dans le `.d.ts`, mais aucune carte ne le montre.
- `conventions.md` décrivait 3 familles alors que le build émet aussi `header`/`footer`/`layout` (14 composants de la vague chrome) : famille « Chrome de page » ajoutée avec l'accord de l'utilisateur. **La validation d'en-tête doit comparer les GROUPES émis (`ls ds-bundle/components/`) aux familles décrites, pas seulement vérifier que les noms cités existent** — une omission ne casse aucun nom mais laisse l'agent refabriquer le composant.

## Re-sync risks (à surveiller au prochain sync)
- **CSS compilé = instantané de l'app** : `buildCmd` recompile via Vite avec `SITE_CSS_PATH=$PWD/src/index.css` — si le thème défaut ou shared.css évoluent, les cartes changent de peau (grades conservés par design, mais re-regarder les planches). Ne JAMAIS builder sans SITE_CSS_PATH (le VITE_SLUG du .env s'impose sinon).
- **Previews liés au code produit** : les 100 fichiers `.design-sync/previews/*.tsx` importent l'API réelle — un rename/suppression de composant casse le preview correspondant (build `! preview build failed` → carte plancher). Les exclusions barrel (TabsSection, GridLayoutSection, HeroSearch, ExpandableActions, HeroEntityBanner floor) sont volontaires.
- **Réseau au build** : polices Google en @import distant ; l'embed YouTube de VideoSection peint via réseau (offline → cadre vide, non bloquant).
